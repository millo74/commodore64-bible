# Scopo

La Commodore 64 Bible è composta da differenti forme di conoscenza.

Non tutti i documenti hanno lo stesso scopo.

Alcuni insegnano.

Alcuni documentano attività di ricerca.

Altri preservano informazioni storiche.

Altri ancora descrivono tecniche di programmazione riutilizzabili.

Questo documento definisce tutti i **Knowledge Artifacts** ufficiali utilizzati all'interno del progetto.

---

# Learning Artifacts

I Learning Artifacts guidano il lettore lungo il **Knowledge Trail**.

## KT -- Knowledge Trail Stage

Rappresenta la più piccola unità di apprendimento.

Ogni Stage introduce un singolo concetto e appartiene a uno specifico Trail.

---

## VP -- Vista Point

Rappresenta un punto di riflessione.

Non vengono introdotti nuovi argomenti.

Il suo scopo è collegare e consolidare le conoscenze acquisite fino a quel momento.

---

## MH -- Mountain Hut

Rappresenta un punto di consolidamento.

Contiene riepiloghi, esercizi, mini progetti e riferimenti prima di proseguire il Trail.

---

## SUM -- Summit

Rappresenta il raggiungimento della padronanza di un intero argomento.

Un Summit conclude un Trail e prepara il lettore ad affrontare quello successivo.

---

# Research Artifacts

I Research Artifacts documentano ricerche, esperimenti e nuove scoperte.

## RN -- Research Note

Documenta una specifica attività di ricerca.

Può contenere ipotesi, misurazioni, risultati sperimentali e conclusioni.

---

## LAB -- Laboratory Experiment

Descrive un esperimento riproducibile dal lettore.

Ogni esperimento dovrebbe produrre risultati misurabili e verificabili.

---

## REV -- Reverse Engineering Report

Documenta l'analisi tecnica di software commerciale, demo o hardware.

L'obiettivo è comprendere il funzionamento interno del sistema, non limitarsi alla riproduzione del codice.

---

# Reference Artifacts

I Reference Artifacts descrivono informazioni tecniche consolidate.

## REF -- Reference

Documento di riferimento tecnico generale.

---

## API -- Programming Interface

Documenta librerie software e interfacce riutilizzabili.

---

## HW -- Hardware Reference

Descrive il comportamento dei componenti hardware, dei registri e dei chip del Commodore 64.

---

## MAP -- Memory Map

Documenta la disposizione della memoria e le differenti configurazioni dello spazio degli indirizzi.

---

## TIM -- Timing Reference

Documenta il numero di cicli macchina, le temporizzazioni e la sincronizzazione con l'hardware.

---

# Design Artifacts

I Design Artifacts descrivono idee progettuali riutilizzabili.

## PAT -- Programming Pattern

Documenta una tecnica di programmazione ricorrente.

Esempi:

* State Machine
* Sprite Manager
* IRQ Dispatcher
* Double Buffer
* Object Pool

---

## ALG -- Algorithm

Documenta un algoritmo riutilizzabile.

Ad esempio:

* Collision Detection
* Path Finding
* Compressione dei dati
* Generazione di numeri casuali

---

## LIB -- Reusable Library

Documenta componenti software riutilizzabili.

---

# Project Artifacts

Questi documenti descrivono il progetto Commodore 64 Bible stesso.

Ne fanno parte, ad esempio:

* Project Philosophy
* Repository Architecture
* Translation Policy
* Knowledge Trail
* Document Templates
* Repository Roadmap

---

# Convenzione di Denominazione

Quando possibile, ogni Knowledge Artifact dovrebbe utilizzare un identificatore univoco.

Esempi:

KT-0001

RN-0017

LAB-0005

REV-0002

PAT-0014

Questa convenzione rende semplici, stabili e durevoli i riferimenti incrociati tra i documenti.

---

# Evoluzione

Nel tempo potranno essere introdotte nuove tipologie di Knowledge Artifacts.

Il sistema di classificazione è progettato per evolversi senza compromettere la documentazione esistente.
