# Purpose

The Commodore 64 Bible is composed of different kinds of knowledge.

Not every document serves the same purpose.

Some documents teach.

Some document research.

Some preserve historical information.

Some describe reusable programming techniques.

This document defines every official Knowledge Artifact used throughout the project.

---

# Learning Artifacts

Learning Artifacts guide the reader along the Knowledge Trail.

## KT -- Knowledge Trail Stage

The fundamental learning unit.

Each Stage introduces one concept and belongs to a specific Trail.

---

## VP -- Vista Point

A reflection point.

No new concepts are introduced.

Its purpose is to connect previously learned ideas.

---

## MH -- Mountain Hut

A consolidation point.

Contains summaries, exercises, mini projects and references before continuing the Trail.

---

## SUM -- Summit

Represents mastery of a complete subject.

A Summit concludes one Trail and prepares the reader for the next.

---

# Research Artifacts

Research Artifacts document discoveries and investigations.

## RN -- Research Note

Documents a technical investigation.

May contain hypotheses, measurements and conclusions.

---

## LAB -- Laboratory Experiment

Describes an experiment that can be reproduced by the reader.

Every Laboratory document should produce measurable results.

---

## REV -- Reverse Engineering Report

Documents the analysis of commercial software, demos or hardware.

The objective is understanding rather than code reproduction.

---

# Reference Artifacts

Reference Artifacts describe stable technical information.

## REF -- Reference

General technical reference.

---

## API -- Programming Interface

Documents reusable software interfaces and libraries.

---

## HW -- Hardware Reference

Documents chips, registers and hardware behaviour.

---

## MAP -- Memory Map

Documents memory layouts and address spaces.

---

## TIM -- Timing Reference

Documents cycle timing and hardware synchronization.

---

# Design Artifacts

Design Artifacts describe reusable engineering ideas.

## PAT -- Programming Pattern

Documents a recurring programming technique.

Examples include:

* State Machines
* Sprite Managers
* IRQ Dispatchers
* Double Buffering
* Object Pools

---

## ALG -- Algorithm

Documents a reusable algorithm.

Examples include:

* Collision Detection
* Path Finding
* Data Compression
* Random Number Generation

---

## LIB -- Reusable Library

Documents reusable software components.

---

# Project Artifacts

These documents describe the Commodore 64 Bible itself.

Examples include:

* Project Philosophy
* Repository Architecture
* Translation Policy
* Knowledge Trail
* Document Templates
* Repository Roadmap

---

# Naming Convention

Whenever possible, every Knowledge Artifact should use a unique identifier.

Examples:

KT-0001

RN-0017

LAB-0005

REV-0002

PAT-0014

This convention makes cross-references simple, stable and future-proof.

---

# Evolution

New Knowledge Artifacts may be introduced as the project grows.

The classification system is intended to evolve without breaking existing documentation.
